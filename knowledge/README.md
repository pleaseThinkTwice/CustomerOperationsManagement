# 知识文件怎么写

小规模知识直接写在本目录。系统每次提问都会读取以下四份文件，与实时读取的数据库 schema 一起完整放入模型 prompt；不做 RAG 检索。

| 文件 | 应填写的内容 |
| --- | --- |
| `表与字段说明.md` | 每张表的粒度、主键、关联键和基数；字段含义、枚举值、单位和刷新频率 |
| `业务术语.md` | 指标定义、同义词、过滤条件、计算方法和歧义时的追问规则 |
| `常见问答.md` | 制度、流程及常见解释；不应写成未经验证的实时数据 |
| `SQL示例.md` | 10 条左右已用只读库验证的问题与 SQL，帮助模型参考正确的连接和过滤方式 |

数据库的真实字段名与类型会自动读取；只需在 `.env` 的 `PROMPT_TABLES` 列出允许查询的表。问数用的数据库账号应是只读账号。修改文件后，下一次提问直接使用新内容，无需重建索引或重启。

先补最常问的 3–5 张表和高频指标。未确认的口径不要写成事实；知识变多超过 3 万字符时系统会报错，届时再评估检索方案。
