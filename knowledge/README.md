# 知识怎么录入

这里的文件就是项目内的业务知识底稿；页面顶部“知识与表说明”可以直接阅读。到公司后先替换演示内容，再把确认过的知识录入 SQLBot。所有实际问数配置都在同一个 SQLBot 页面里，不需要打开其他文档网站。

| 知识类型 | 修改的项目文件 | 在 SQLBot 录入的位置 |
| --- | --- | --- |
| 数据库结构 | 数据库自动同步 | 数据源 → 表管理 |
| 表介绍、字段解释、状态枚举 | `表与字段说明.md` | 数据源 → 表管理 → 表/字段描述 |
| 表之间的 JOIN 关系 | `表与字段说明.md` | 数据源 → 表关系管理 |
| 指标、业务术语、同义词 | `业务术语.md` | 设置 → 术语库 |
| 正确的“问题 → SQL” | `SQL示例.md` | 设置 → SQL 示例库 |
| 日常 QA | `常见问答.md` | 当前先作为整理底稿；SQLBot 的术语库只适合问数口径，不应把通用 FAQ 全塞进去 |

建议优先完善高频的 3–5 张表：每张表写清粒度、主键、关联键与关联基数、金额单位、时间字段、状态枚举。再整理 10 条高频业务问题，用已核对的 SQL 和参考结果逐一测试。对于未确认的口径，不要写成模型必须遵守的规则。

小文档可以先人工整理，定期核对版本和维护人。等 FAQ 量变大，再考虑在同一入口接文档检索；本项目目前没有实现通用文档问答，不会假装 SQLBot 的术语库能回答所有 FAQ。
