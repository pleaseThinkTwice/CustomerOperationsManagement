# 客户运营管理平台 · 页面逻辑问题清单

> 依据：`客户运营管理平台离线演示.html`（分支 `claude/modest-ride-5jizam`）的前端代码与离线 mock 数据，配合浏览器逐页打开核对。
> 页面本身的逻辑见 [页面逻辑说明.md](./页面逻辑说明.md)。
> 级别：**高** = 口径或数据源冲突，数字会对不上、可能误导判断；**中** = 流程断点或功能缺失；**低** = 体验、文案、一致性。
> 标「待后端确认」的条目只在离线 mock 里看到，真实接口可能已处理。

## 一、跨页面问题（优先处理）

| # | 级别 | 问题 | 涉及页面 | 建议 |
|---|---|---|---|---|
| X1 | 高 | **「过保」有三套口径**：① 质保信息管理按 OEM × 电芯容量 × PN 的质保年限 / 里程判定；② 非常规外发「排除过保」用页面上手填的里程 / 年限阈值；③ 首页项目视角「适用车型 & 质保」按车型维护质保条款，且可行内编辑。同一台车在不同页面可能一个算在保、一个算过保。 | 预警闭环（质保信息管理、非常规外发）、首页项目视角 | 以质保信息管理为唯一来源：非常规外发的过保排除直接读取 PN 质保信息（去掉手填阈值）；项目视角的车型质保改为只读，显示来自质保信息管理的值。 |
| X2 | 高 | **过保率分母不一致**：首页客户 / 项目视角「过保率 = 过保数 / 累计出货(Pack)」；质保统览「过保率 = 过保车辆数 / 车辆数」。 | 首页、预警闭环 | 统一为同一分母（建议按车辆，即过保车辆 / 接入车辆），并在两处用同一个函数计算。 |

| X5 | 中 | **待办不全**：我的待办只汇总会议任务、认领预警、部门需求。复核任务里被指定的复核人、需求管理里的责任人、项目管理里的任务责任人都看不到自己的待办。 | 我的待办、预警闭环、需求管理、项目管理 | 把复核任务（按复核人）、需求管理（按责任人）、项目管理任务（按责任人）接入 `/api/workbench/my_todos`。 |
| X6 | 中 | **两套需求流程并存**：需求管理（关联客户，待审批 → 通过 / 驳回，没有完成状态）和部门需求池（不关联客户，有完成时间）；会议纪要「转需求」只进需求管理，我的待办只收部门需求池。 | 需求管理、部门需求池、会议纪要、我的待办 | 合并为一个需求模型，用「来源（客户 / 部门内部）」区分；统一状态机：待审批 → 已通过 → 进行中 → 已完成 / 已驳回。 |
| X7 | 中 | **知识入口重复**：Q&A 知识库、知识中心、数智分析知识库、数据洞察四个入口，知识中心里又嵌了前三个。 | Q&A 知识库、知识中心、数智分析、数据洞察 | 侧栏只保留「知识中心」作为入口，Q&A 管理、数据洞察作为它的子页；数智分析里的「查询手册 / 工具箱」按钮改为跳转同一处。 |
| X8 | 中 | **协议 / 合同文件分散在三处**：文档管理（三类协议文件）、合同管理（原合同文件）、客户档案详情的「合作协议」页签。 | 文档管理、合同管理、客户档案 | 合同管理作为合同与协议的唯一台账；文档管理只放非合同类资料；客户档案的协议页签改为读取合同管理。 |
| X9 | 中 | **侧栏「预警闭环」角标含义过时**：角标数 = 预警记录里「未闭环」条数，而预警闭环页现在的主线是外发规则、复核任务；预警记录退到第四个 Tab。 | 全局、预警闭环 | 角标改为「未完成的复核任务数」（或「我负责的未完成复核任务」），与待办口径一致。 |
| X10 | 中 | **会议记录分散**：会议纪要页之外，项目管理里也有「会议纪要」「周会」功能，各自存储。 | 会议纪要、项目管理 | 项目管理的会议纪要写入会议纪要模块（客户为空或标记为内部会议），只保留一份会议数据。 |
| X11 | 低 | **时间筛选的作用范围不统一**：客户视角说明「只作用于走势图和质量分析」；电芯视角的失效率走势、失效模式构成、SOH 分布不随时间筛选变化，质量分析却会变。 | 首页 | 明确规则：走势类卡片都随时间筛选；累计类 KPI 不随。电芯视角失效率走势按所选时间范围取月份。 |

## 三、建议处理顺序

1. **统一口径**（X1、X2、X3、P2-1、P4-1、P4-2）：过保、过保率、失效计量、客户等级。这些会直接导致不同页面数字对不上。
2. **打通流程**（X5、X6、P4-3、P4-5、P5-1）：待办汇总、需求状态机、复核结论到外发和预警记录的流转、阶段总结自动汇总。
3. **合并重复入口**（X7、X8、X10）：知识、合同 / 协议、会议。
4. **体验与文案**：其余低级别条目。
