# 业务逻辑与口径

后端按页面分模块实现，本文写清每个模块「数据从哪来、怎么算、状态怎么流转」。接口清单见 [API.md](./API.md)，要准备的数据表见 [数据需求.md](./数据需求.md)。

## 0. 总体

- **两个数据源**：运营库（平台自己的业务数据，读写）+ 分析库（数仓，只读）。所有看板指标都从分析库现算，运营库只存人维护的数据（档案、会议、闭环台账、质保条款、需求等）。
- **一套 SQL 两处跑**：分析口径集中在 `src/analytics/index.js`，同一条 SQL 在本地 sqlite 演示库和公司 Doris 上都能跑（月份 / 年份 / 日期函数按方言切换）。
- **登录与权限**：账号密码登录（scrypt 哈希），会话 Cookie `cop_sid`（默认 12 小时）。权限码分两类：页面可见 `pageN.view`、编辑权限（`customer.edit`、`warning.edit`、`demand.approve`、`user.manage` 等），管理员角色是 `*`。用户可单独覆盖「可见模块」，并可限定只看哪些客户（OEM 数据权限）。所有写操作记操作日志，登录记登录日志，页面访问记行为埋点。
- **AI 能力**：所有 AI 接口都有规则兜底，不配大模型也能用。前端以 `stream:true` 发起时立即返回 `task_id`，再轮询 `/api/task/progress/:id`。QA / 知识库 / text2sql 由另一模块（`src/ai`）提供，存在时自动挂载。
- **通知**：默认只记日志；配置 webhook 后推送到企业微信 / 飞书 / 钉钉机器人或公司消息网关。

## 1. 首页看板（page1）

三个视角共用一组筛选：客户、容量、时间范围。

### 指标口径

| 指标 | 口径 |
|---|---|
| 累计出货 | `dws_shipment` 按 ship_level 汇总 qty：电芯 / 模组 / Pack 三个数 |
| 累计接入 | `dwd_vehicle_access` 行数（一车一行） |
| 接入率 | 接入车辆 ÷ Pack 出货 |
| 活跃车辆 | 最近上线日期在近 30 天内的车 |
| 近 15 天接入 / 今年接入 | 首次接入日期落在区间内的车 |
| pack_id 缺失 | 接入车辆中 pack_id 为空的车；缺失率 = 缺失 ÷ 接入 |
| 过保数 | 接入车辆中「质保起算日 + 年限 已到期」或「累计里程 > 质保里程」的车。条款按 客户 × 容量 × 车型 取，乘用 / 营运分开；优先平台质保设置，其次数仓质保政策，都没有时按 8 年、不限里程 |
| 在保 | 接入 − 过保 |
| 预警外发 / 已闭环 | `dwd_warning` 中 is_outgoing=1 的条数 / 其中 is_closed=1 |
| 近 7 天预警 / 闭环 | 触发时间在近 7 天内的外发预警 / 其中已闭环 |
| 预警超期（alarmOverdue） | 外发、未闭环、触发超过 7 天 |
| 失效车辆（电芯视角） | 现场工单（wo_type=现场）涉及的去重 VIN 数 |
| 失效率 ppm（电芯视角） | 失效车辆 ÷ 接入车辆 × 10⁶ |
| 失效率走势 | 近 10 个月每月末的 累计失效车辆 ÷ 累计接入车辆 × 10⁶，按客户 |
| 批次 ppm | 批次外发预警数 ÷ 批次电芯出货 × 10⁶；≥30 预警中，≥10 关注 |
| PN 追溯 | 电芯出货按 PN × 客户汇总，对上该 PN 的现场工单车辆数；前端算 ppm 和状态（高于平均 25% 预警中、5% 关注） |
| SOH 分布 | 按客户统计各 SOH 区间（<90、90~92 … 98~100）车辆占比 |
| SOH 箱线 | 按累计里程（0~2万 … 20万+）或累计循环（0~100 … 1200+）分桶，每桶 SOH 的 min / Q1 / 中位 / Q3 / max 和样本数；整体 + 按 Pack PN |
| 质量矩阵 | 近 48 个月，按失效模式 × 月份：外发预警数、闭环数、客诉数，以及工单数（合计和预警 / 批改 / 现场三类） |
| 高风险电芯 | 外发未闭环的预警按 SOH 升序；SOH < 70 标「需更换」，否则「待核查」 |

### 三视角

- **客户视角**：所选客户的 KPI、接入走势（月 / 年 / 近 15 天）、各容量项目表（电芯体系、成组方式、SOP、出货、接入、接入率、pack_id 缺失、过保、预警）、质量矩阵、关键人、拜访计划、近期会议、大事记、我的待办完成情况。
- **项目视角**：客户 × 容量。基本信息（成组、串数、SOP、质保条款）、各车型接入 / pack_id 缺失 / 过保 / 预警、质保条款表（来自平台质保设置，可编辑，带 id）、SOH 箱线、质量矩阵、活跃车辆、疑似调表数。
- **电芯视角**：某容量下各客户横向对比：出货、接入、pack_id 缺失、失效车辆、失效率、失效模式构成、SOH 分布、失效率走势、PN 追溯、批次 ppm、高风险电芯。

### 其他

- 旧版客户看板接口 `/api/dashboard/fast`（运营库，快）和 `/api/dashboard/doris`（数仓，慢）分开，前端先渲染快的再补慢的。
- 车辆明细（活跃车辆、疑似调表）支持分页和 xlsx 导出。
- 自定义模块：用户保存的图表定义；「AI 生成」把一段描述解析成图表，无大模型时识别「名称 数值」行。

## 2. 我的待办（page17）

按当前登录人姓名汇总三类：会议任务（负责人是我）、认领预警（负责人是我）、部门需求池（我提报或我负责）。会议任务计划日期已过且未完成显示「已逾期」。完成判定：已完成 / 已闭环 / 已通过。

## 3. 客户档案（page2）

客户、关键人（内部 / 外部）、拜访计划、大事记。关键人支持下载模板和 xlsx 导入。删除客户会删除其关联数据。容量、产品、客户组等下拉来自数仓维表。

## 4. 会议纪要（page3）

- 会议 + 共识条目 + 待办任务 + 归档材料。列表分页，可导出 xlsx，可批量创建。
- **AI 提取纪要**：有大模型时按 JSON 结构抽取；没有时按规则：首行作标题，识别日期、参会人，「共识 / 决议 / 结论」段落作共识，含「负责 / 待办 / 行动」的行作任务，并识别「负责人：xxx」「截止 yyyy-mm-dd」。支持多份批量提取（带进度）。
- 任务状态只有负责人本人或有会议编辑权限的人能改；可一键给未完成任务的负责人发提醒。

## 5. 预警闭环（page4）

- **闭环台账**（运营库 warnings）：客户 × 容量 × 失效模式一条，人工维护闭环状态。改为「已闭环」时自动记录闭环人和日期并清空未闭环原因；改回「未闭环」时清空闭环信息。
- **外发规则**、**失效模式判定逻辑**：运营库维护，看板失效模式表会带出对应的判定逻辑文本。
- **质保信息管理**：平台质保设置（客户 × 容量 × 车型 × PN，乘用 / 营运各一套年限、里程、SOH）。可从数仓质保政策初始化（已有的不覆盖），或解析 `data/import/warranty.xlsx`（`force=1` 覆盖）。看板过保判定优先用这里。
- **AI 预警分析**：汇总数仓口径（外发、闭环率、近 7 天、超期、客诉、失效模式 Top）和台账（未闭环条目），有大模型时生成分析，否则按规则给结论和建议，结果存档可回看。

## 6. 阶段总结（page5）

- 「生成本周快照」：对每个客户 × 失效模式，取本周（周一起）外发数，与上周比较，`reduced_breakdown = 上周 − 本周`。同一周重复生成会覆盖更新。
- 可标记 / 取消里程碑并写说明，可导出 xlsx，可按收件人发邮件（走通知通道）。

## 7. 需求管理（page10）与部门需求池（page16）

- **客户需求**：来源客户、背景、标签、负责人、优先级、截止日期，可从会议转入。状态：待审批 →（审批）已通过 / 已驳回；审批可选通知负责人。AI 拆解：把一段描述拆成多条需求，无大模型时按句子和关键词（紧急 / 尽快 → 高优先级）拆分。
- **部门需求池**：提报 → 待审批 → 审批通过 / 驳回 → 完成（填实际完成日期）。只有提报人或审批人能改；审批人 = 有 `demand.approve` 权限的用户；`_reopen` 可重新打开。

## 8. 合同管理（page12）

主合同 / 补充协议树，统计（总数、总金额、按状态 / 类型 / 客户）、附件上传与预览、xlsx 导入导出。导入按合同编号新增或更新，「主合同编号」列用来挂补充协议。

## 9. 文档管理（page7）

按客户 × 容量 × 文档类型上传与下载。同名文件已存在时返回 409，前端确认后带 `overwrite` 覆盖。

## 10. OEM 映射（page8）

平台客户编码 ↔ 数仓客户组名称。数仓侧客户组列表带接入车辆数，便于对照。

## 11. 系统管理（page11）

用户（新建默认需首次登录改密）、启停用、角色与权限、个人可见模块覆盖、客户数据权限、自定义列、登录日志、操作日志、行为统计（按页面 / 按人 / 按天）。

## 12. 项目管理（page13）

- 任务树：方向 → 迭代 → 任务 → 子任务；统计按状态 / 负责人 / 方向。
- 周视图按 ISO 周（`2026-W38`），汇总本周完成 / 进行中 / 待办 / 逾期、会议、未闭环预警、待处理需求；周会议程可编辑，可在周会上认领事项（需求 / 预警 / 待办 / 任务）。
- 周报 / 月报导出 Markdown；会议纪要导出 Word；可把项目会议导入运营会议纪要（已导入返回 409，`merge=true` 覆盖）。

## 13. 数据洞察（page14）

对分析库的表做「学习」：行数、每列去重数和空值率；时间列出按月趋势，低基数分类列出 Top10 分布；规则化结论（数据量、时间覆盖、最近一月环比、Top1 集中度、空值率异常），配置大模型时再补业务结论。洞察可收藏、跟进、检索、导出、生成报告、关联共享字段的其他表并算匹配率，可同步到知识库。自由查询只允许单条只读 SELECT，自动加 LIMIT。

## 14. 工具箱（page19）、系统导航（page15）、意见反馈

- 工具：参数化只读 SQL 模板。`{{逻辑表名}}` 替换成分析库实际表名，`:参数` 作为绑定参数（防注入）。
- 系统导航（ADG）：系统链接维护；业务手册读 `data/handbooks/` 下的 xlsx / csv。
- 意见箱：提交与查看。

## 待你决策的口径（来自页面逻辑问题清单）

后端已经按下面的「当前做法」实现，改口径只需要动 `src/analytics/index.js` 或对应路由，不影响前端结构。

| # | 问题 | 当前做法 | 建议 |
|---|---|---|---|
| X1 / P1-1 / P4-1 | 过保有多套口径 | 看板过保统一读质保信息管理（平台质保设置），没有再读数仓政策。项目视角的车型质保改的就是同一张表，所以两边已经一致 | 页面层面再把项目视角改只读、非常规外发去掉手填阈值 |
| X2 | 过保率分母 | 后端只给过保数，比率由前端算 | 统一为 过保车辆 ÷ 接入车辆 |
| X3 | 失效计量单位混用 | 电芯视角 KPI / 对比表 / 失效模式构成 / 走势都按「失效车辆」（现场工单去重 VIN）；PN 追溯按「失效车辆 ÷ 出货电芯颗数」；批次 ppm 按「外发预警数 ÷ 出货电芯颗数」 | 需要确认电芯级失效颗数的数据来源（工单是否带电芯数），有的话 PN 追溯和批次改成颗数口径 |
| X4 | 失效模式没有统一字典 | 失效模式直接取数仓 fault_type 原值 | 建失效模式字典表（建议放运营库），复核项、预警原因挂字典 |
| X5 | 待办不全 | 已汇总会议任务、认领预警、需求池 | 复核任务、客户需求负责人、项目任务接入待办（后端已有数据，确认后加） |
| X6 | 两套需求流程 | 两套分开实现 | 合并时用「来源」区分，统一状态机 |
| P12-1 | 合同过期仍算执行中 | 状态按人工维护返回 | 统计时按到期日自动校正为「已到期」 |
