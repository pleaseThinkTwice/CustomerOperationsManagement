# 数据需求：公司侧需要准备什么

平台的数据分两类，接入方式不同：

| | 运营库（平台自有） | 分析库（公司数仓 / test 库） |
|---|---|---|
| 内容 | 客户档案、会议、待办、需求、合同、预警闭环台账、质保设置、用户权限、日志等 | 出货、接入车辆、预警、工单、调表、质保政策 |
| 读写 | 平台读写 | 平台**只读**（只发 SELECT） |
| 建表 | 服务启动自动建表，不用管 | **需要公司侧提供**，本文就是清单 |
| 默认 | 本地 sqlite `data/ops.sqlite` | 本地生成的演示库 `data/analytics-demo.sqlite` |
| 切换 | `OPS_DB_DRIVER=mysql` + `OPS_DB_URL` | `ANALYTICS_DB_DRIVER=mysql` + `ANALYTICS_DB_URL`（Doris 走 MySQL 协议） |

字段、类型、Doris 建表语句见 [数据表DDL.md](./数据表DDL.md)。

## 一、分析库 8 张表

逻辑表名是代码里用的名字。公司的真实表名不同时，用环境变量映射，不改代码：

```bash
ANALYTICS_TABLE_PREFIX=test.                          # 所有表统一加库名前缀
ANALYTICS_TABLE_dwd_vehicle_access=test.ods_xxx_vehicle  # 单表覆盖
```

字段名不同时，**推荐在 Doris 建视图对齐字段名**，平台就能原样跑。例：

```sql
CREATE VIEW test.cop_dwd_vehicle_access AS
SELECT vin, device_id AS deviceid, cust_code AS oem, CAST(cell_cap AS VARCHAR) AS cell_cap, ...
FROM test.dwd_xxx_vehicle;
```

| 逻辑表 | 粒度 | 用在哪里 | 必需字段 |
|---|---|---|---|
| `dim_oem` | 一个客户一行 | 客户下拉、OEM 映射页的客户组 | oem, oem_ch, cust_grp_name |
| `dim_cell_product` | 客户 × 容量 × 车型 | 容量下拉、项目列表、电芯体系 / 成组 / SOP、项目视角基本信息 | oem, cell_cap, cell_structure, cell_type, vehicle_model, series_count, sop_date, pn_system, plant |
| `dws_shipment` | 出货批次 | 累计出货（电芯 / 模组 / Pack）、接入率分母、批次 ppm、PN 追溯 | oem, cell_cap, vehicle_model, ship_level(cell/module/pack), qty, ship_date, pn, batch_no, plant |
| `dwd_vehicle_access` | 一车（Pack）一行 | 接入数、活跃车辆、近 15 天接入、今年接入、过保、pack_id 缺失、SOH 分布 / 箱线、接入走势、车辆明细导出 | vin, deviceid, oem, cell_cap, cell_structure, vehicle_model, pack_pn, pack_id, usage_type, access_date, last_online_date, warranty_start_date, mileage_km, soh, cycle_count |
| `dwd_warning` | 一条预警一行 | 预警外发 / 闭环 / 客诉、近 7 天、超期、失效模式、质量矩阵、批次 ppm、高风险电芯、阶段总结快照、AI 预警分析 | warning_id, vin, oem, cell_cap, vehicle_model, fault_type, warning_time, is_outgoing, is_closed, close_time, is_complaint, batch_no, pack_no, cell_pos, soh |
| `dwd_work_order` | 一张工单一行 | 质量矩阵「工单」页签、电芯视角失效车辆 / 失效率 ppm / 失效模式构成 / 失效率走势 / PN 追溯 | wo_id, wo_type(预警/批改/现场), vin, oem, cell_cap, vehicle_model, pn, fault_type, create_time, close_time, plant |
| `dwd_mileage_adjust` | 一次检测一行 | 疑似调表车辆数与明细 | vin, oem, cell_cap, check_date, mileage_diff_km |
| `dim_warranty_policy` | 客户 × 容量 × 车型 | 初始化平台质保设置；平台没设置时作为过保判定依据 | oem, cell_cap, vehicle_model, pn, passenger_/commercial_ years / mileage / soh |

### 取值约定（对不上会导致数字为 0）

- `oem` 与平台客户档案的 `customers.oem` 用同一套编码（如 XMS、BYD）。不一致时在 OEM 映射页维护，或在视图里转换。
- `cell_cap` 存纯数字字符串（`153`，不带 `Ah`）。平台会去掉前端传来的 `Ah` 后缀再比较。
- `ship_level` 取 `cell` / `module` / `pack` 三个值。
- `usage_type` 取 `passenger` / `commercial`，决定用乘用还是营运质保条款。
- `is_outgoing` / `is_closed` / `is_complaint` 为 1/0。
- `wo_type` 取 `预警` / `批改` / `现场`。
- `fault_type` 在预警表与工单表用同一套失效模式名称（建议建字典，见业务逻辑说明「待决策」）。
- 日期字段 `YYYY-MM-DD`，时间字段 `YYYY-MM-DD HH:MM:SS`。
- `pack_id` 为空或空串计入「pack_id 缺失」。
- `dws_shipment.pn`：电芯层级出货填电芯 PN；`dwd_work_order.pn` 填同一套电芯 PN，PN 追溯靠它关联。
- `dwd_vehicle_access.pack_pn` 与质保条款的 `pn` 用同一套 Pack PN，SOH 箱线按它分组。

### 数据量与性能

看板的查询都是按 oem / cell_cap 过滤后 GROUP BY，Doris 上没有问题。两处在应用里计算，数据量大时要注意：

- **过保判定**：按 分组 × 用途 各跑一次 COUNT（条款不同），组数一般几十个。
- **SOH 箱线**：取所选客户 × 容量的 soh / 里程 / 循环到内存算分位数。单项目几十万车可以接受；更大时建议数仓出一张按 PN × 区间预聚合的分位数表，再改 `analytics.sohBox` 读它。

## 二、到公司后的接入步骤

1. 在 `.env` 配置分析库（复制 `.env.example`）：
   ```bash
   ANALYTICS_DB_DRIVER=mysql
   ANALYTICS_DB_URL=mysql://只读账号:密码@doris-fe:9030/test
   ANALYTICS_TABLE_PREFIX=test.
   ```
2. 安装驱动：`npm i mysql2`（只有用 mysql/Doris 时需要）。
3. 运行自检：`npm run check-analytics`。逐表逐字段检查，列出缺表、缺字段、行数和一行样例。全部 ✓ 后启动服务。
4. 质保条款：把 `质保.xlsx` 放到 `data/import/warranty.xlsx`（列：客户 / 容量 / 车型 / PN / 乘用年限 / 乘用里程 / 乘用SOH / 营运年限 / 营运里程 / 营运SOH），在预警闭环 → 质保信息管理点「解析 Excel」。没有文件时从 `dim_warranty_policy` 初始化。
5. 业务手册：把 xlsx / csv 放到 `data/handbooks/`，系统导航里的手册直接读。
6. 运营库要放公司 MySQL 时：`OPS_DB_DRIVER=mysql`、`OPS_DB_URL=mysql://...`，首次启动自动建表并写入初始角色和管理员（`ADMIN_PASSWORD` 设初始密码）。不想要演示数据设 `SEED_DEMO=0`。
7. 可选：
   - 大模型：`LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`（OpenAI 兼容）。不配置时会议纪要提取、预警分析、周报等走规则兜底。
   - 通知：`NOTIFY_DRIVER=webhook`、`NOTIFY_WEBHOOK=<企业微信/飞书/钉钉机器人地址>`。默认只写日志。
